# QA-001 — Static review of navigation requirements and code (Home → Visuals)

**Exercise status:** Completed

**Training context:** ENI Software Tester training
- Module 01 — Introduction to software testing (concepts applied)
- Module 02 — Static testing (main objective)

**Type:** Static testing (review of requirements and source code, without executing the program)

## Context
Navigation between the homepage and the VISUALS section of Meily Lab.
The exercise covered two activities:
1. Review of an initial requirement describing this navigation.
2. Targeted static review of the source files involved in this navigation.

## Expected behaviour
From the homepage, the user can open the VISUALS section.
The initial requirement under review did not define this behaviour precisely enough (see Investigation).

## Observed behaviour
Static review (code read, not executed):
- The homepage contains the link `<a href="/visuals/">VISUALS</a>` (`src/main.js`).
- `src/visuals.js` defines the three categories MAIN, ASTROLOGY and COLLABS, each displayed with a call to the `gallery()` function.
- No proven code defect was found in the reviewed scope.

Separate dynamic activity: the navigation had been observed in the browser before the static review. This observation is not part of the static review results.

## Steps to reproduce
Not applicable — no defect was reproduced.

Review steps followed:
1. Analyse the initial navigation requirement and list its defects.
2. Write a more precise version of the requirement.
3. Critically review that new version.
4. Read the navigation files and locate the link and the VISUALS categories in the code.

## Environment
- Static review of the source code (state of commit `d043e47`).
- Files reviewed: `index.html`, `src/main.js`, `visuals/index.html`, `src/visuals.js`, related CSS excerpts (`src/style.css`, `src/visuals.css`).
- Browser used for the earlier dynamic observation: Not documented.

## Severity
Not applicable — no code defect identified.
The defects found concern the requirement wording, not the application behaviour.

## Investigation

**1. Defects found in the initial requirement**
- Interactive elements not defined.
- The term "rapidement" (quickly) is not measurable.
- Expected information on the VISUALS page not specified.
- Opening behaviour insufficiently defined.

**2. Proposed improved requirement**
- Identifies the sections of the site involved.
- Proposes a loading time of less than one second.

**3. Critical review of the proposed requirement**
- Some wording remained imprecise: compatibility with "all browsers", "consistent information".
- The one-second threshold was not formally validated.

**4. Targeted static code review**
- Identified the HTML link `<a href="/visuals/">VISUALS</a>` in `src/main.js`.
- Searched `src/visuals.js` independently and identified the three categories MAIN, ASTROLOGY and COLLABS and the calls to `gallery()`.
- Distinguished verified observations, hypotheses and missing information.

**Limits of this review**
Performance, browser compatibility and full navigation behaviour were not validated: a static review cannot confirm them.

## My diagnosis
- The requirement contained ambiguities (undefined elements, non-measurable terms).
- The code in the reviewed scope contains the expected link and categories; no code defect was found.
